# @relay/server

Edge tier — Cloudflare Workers. Shape proxy and write endpoint.

**Holds:** the session-sealing key. Nothing else.
**Never:** provider credentials, model output, untrusted content.

`src/auth/unsealSession.ts` must be the _only_ place the AuthKit cookie is parsed —
both the shape proxy and the write endpoint call it. Two implementations will drift.

Every shape request passes through here before the CDN, so this is the highest-leverage
cost line in the stack (H8). Keep it on edge compute and keep it cheap per request.

## WorkOS

**WorkOS is not run locally.** Point `.env` at a real environment that never serves
production traffic, from the dashboard:

| Where     | What                                                       |
| --------- | ---------------------------------------------------------- |
| API Keys  | `WORKOS_API_KEY=sk_test_…`                                 |
| API Keys  | `WORKOS_CLIENT_ID=client_…`                                |
| Redirects | the local callback URL — needed once the login flow exists |

`WORKOS_COOKIE_PASSWORD` is generated by `pnpm run up secrets`. `pnpm health` fails while any
`set-me` remains.

Postgres is a **read replica** of WorkOS: `users`, `organizations` and
`organization_memberships` arrive by webhook and are read-only in application code. Nothing
seeds them — rows exist because the real flow created them. `pnpm health` checks that every
id in Postgres still exists upstream, because one that does not is a dangling foreign key
waiting for a login to hit it.

Filled in Phases 1–3.

## Running it

```
pnpm --filter @relay/server dev     # wrangler dev on :8787
```

Wrangler reads `.env` directly via `--env-file`, so there is no second copy of the secrets in
a `.dev.vars`.

| Route            |                                                                          |
| ---------------- | ------------------------------------------------------------------------ |
| `/`              | signed-in state, or a sign-in button                                     |
| `/auth/login`    | redirect to AuthKit's hosted UI                                          |
| `/auth/callback` | exchange the code, seal the cookie                                       |
| `/auth/logout`   | clear the cookie, revoke the WorkOS session                              |
| `/auth/session`  | the raw `{userId, organizationId}` every authorisation decision keys off |

**Register `http://localhost:8787/auth/callback`** in the WorkOS dashboard under Redirects,
or the hosted login page refuses the round trip with `invalid_redirect_uri`. `pnpm health`
checks this.

`src/auth/session.ts` holds `unsealSession()` and it is the only place the cookie is parsed —
the shape proxy and the write endpoint will both call it. A second implementation would
drift, and the drift would be an authorization bug.
